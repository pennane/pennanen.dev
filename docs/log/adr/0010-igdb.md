# 10. IGDB gives games their identity; the log is not a wiki

**Status:** accepted · 2026-11-10

## Context

Games come from Steam, but ap also wants to add games Steam never saw
(Minecraft, flash games). A game needs an identity that works across sources
([ADR 4](./0004-claims-and-verdicts.md)). IGDB has one for nearly every game,
and maps Steam app ids to it.

ap does not want a game wiki. Public pages show the game and ap's take on it,
nothing more.

## Decision

- IGDB is a source like Steam: its answer is stored as a claim with the IGDB
  id as `external_id`. ap's overrides still win.
- Steam games are matched by app id through IGDB's external games, during the
  nightly job and on demand. An app id match is exact, so nobody confirms it.
- Games IGDB can't match by app id stay unmatched until ap picks a game in the
  admin or answers **no match**. "No match" is stored as IGDB's claim with no
  id, so it is never asked again.
- Quick-add searches IGDB, leaving out DLC, bundles, packs, updates and
  editions; remakes, remasters and ports are separate games. A game already in
  the log opens its entry instead of being added twice. When IGDB has nothing,
  ap adds the game by title alone.
- Two images: `cover` is wide (the Steam header first, then IGDB artwork or a
  screenshot) and `poster` is tall (IGDB box art). Pages pick the one that
  fits.
- IGDB contributes title, release date, genres, developers, platforms and
  images. Games have no `description` field: the log shows ap's words, not a
  summary of the game.

## Consequences

- After matching, titles and genres of Steam games switch to IGDB's, which
  rank above the Steam store.
- When two items turn out to be the same IGDB game (a quick-added game later
  synced from Steam), the second match is refused and reported. Merging is
  not built yet.
- Needs a Twitch developer app (`IGDB_CLIENT_ID`, `IGDB_CLIENT_SECRET`).
  Without it the IGDB features answer 503 and everything else works.
